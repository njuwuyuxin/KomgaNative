# 国际化（i18n）

> 阶段 G 的落地记录。目标：默认跟随系统语言，English / 中文完整；语言可在设置里切换并持久化。
> 中文字体子集（中文黄金图）是阶段 G 的剩余项，见文末「边界」。

## 文件与生成

| 文件 | 作用 |
|---|---|
| `apps/app/l10n.yaml` | `flutter gen-l10n` 配置：ARB 目录、模板文件、输出类、`nullable-getter: false`、生成后格式化 |
| `apps/app/lib/l10n/app_en.arb` | 英文模板（所有 key 与 placeholder 类型的真值） |
| `apps/app/lib/l10n/app_zh.arb` | 中文翻译 |
| `apps/app/lib/l10n/app_localizations*.dart` | **生成物，不要手改**（`flutter gen-l10n` 输出） |
| `apps/app/lib/l10n/l10n.dart` | 应用实际使用的 delegates 列表（见下） |

生成命令（仓库根或 `apps/app`）：

```bash
cd apps/app
flutter gen-l10n
```

`tool/ci.dart check` 的 `codegen` 步骤会自动处理：只要 ARB 或 `l10n.yaml` 比生成物新，
或生成物缺失，就先跑 `flutter gen-l10n`。因此**全新 clone（未提交生成物）也能过门禁**。
生成物本身没有手写内容，重跑即可恢复。

## 为什么 delegates 不直接用生成代码里的列表

生成代码的 `AppLocalizations.localizationsDelegates` 固定引用
`flutter_localizations` 的 `GlobalMaterialLocalizations` / `GlobalCupertinoLocalizations`。
本项目的 Material 控件来自 `material_ui` 包，`MaterialApp` 需要的是 **同一套**
`MaterialLocalizations` 类型；直接用生成列表时中文会报：

```text
A MaterialLocalizations delegate that supports the zh locale was not found.
```

所以 `lib/l10n/l10n.dart` 用 `material_ui` 导出的
`GlobalMaterialLocalizations.delegates`（它同时带 Material / Cupertino / Widgets）拼出
`appLocalizationsDelegates`。入口与测试统一用它，不要再手写 delegates 列表。

## 语言设置

- `SettingsState.language`：`AppLanguage.system / en / zh`，默认 `system`。
- `SettingsController.setLanguage` 立即改状态并写入 `SettingsStore`（secure storage，
  key `komganative.settings.v1`，JSON blob）；构造时异步恢复，**未知/坏存档一律回 `system`**。
- `KomgaApp` 只在这一处接线：`locale`、`localizationsDelegates`、`supportedLocales`。
  `locale` 为 null 时交给 Flutter 按系统语言在 `supportedLocales` 里挑。
- 设置页「Appearance」区有 Language 选项（跟随系统 / English / 中文）。

## 文案约定

- 所有用户可见的静态 UI 文案都进 ARB；英文值必须与改造前**逐字一致**，这样英文黄金图不变。
- 带参数的文案用命名 placeholder，并在英文模板里声明类型（`int` / `String`），例如：
  `"{count} pages"`、`"Showing {shown} of {total} books"`。
- 枚举 → 文案的映射放在 UI 层（`reader_mode_text.dart` 等），数据层只保留枚举。
- 加文案流程：两个 ARB 同时加 key → `flutter gen-l10n` → 调用点用
  `AppLocalizations.of(context).yourKey`（`nullable-getter: false`，不需要判空）。

## 测试

- `apps/app/test/l10n_test.dart`
  - 设置页在 `en` / `zh` 下关键文案不同（`Settings` vs `设置`、`Language` vs `语言`）；
  - 完整 App 通过设置切到 English，路由内文案立即切换，并断言写回存档；
  - 未知语言存档回 `system`；
  - `appLanguageFromCode` 对 null / 空串 / 大小写不对 / JSON 残片等坏值一律回 `system`。
- 其他 widget/golden 测试的 `MaterialApp` 都显式带 `locale: en` 与
  `appLocalizationsDelegates`，避免依赖运行机器的系统语言。
- 英文黄金图保持不变；唯一变化是 `settings@eink` 新增 Language 行（见 README）。

## 边界：数据层文案尚未本地化

本次**没有**翻译数据层/控制器生成、再交给 UI 显示的文本：

- `apps/app/lib/src/data/shelf_failure.dart` 的 `ShelfFailure.message/hint`
  （书架、系列、阅读器错误态与重试提示）——保持英文；
- `apps/app/lib/src/session/session_controller.dart` 的 `SessionDisconnected.error/hint`
  （连接失败提示）——保留现有文案，不随语言设置变化。

原因：这些字符串在网络/会话层生成，拿不到 `BuildContext`；要本地化需要先把状态改成
"语言无关的失败类型 + 参数"，再由 UI 翻译。这是后续切片的工作，不在本阶段范围内。
因此当前截图/真机上如果切到中文后仍看到少量英文（或历史中文）错误提示，属于已知边界，
不是漏抽 ARB 的普通文案。

## 中文字体与中文黄金图（2026-11-18 解决，见 ADR 0004）

- **App 不打包中文字体**，走系统字体（Android Noto CJK / iOS 苹方）。
- **黄金图**加载 `apps/app/test/fonts/NotoSansSC-Regular-subset.ttf`（OFL，仅测试用），
  作为 Roboto 的 `fontFamilyFallback`；`pumpGoldenScreen(locale: const Locale('zh'))` 出中文基线，
  首张是 `connection@phone_light_zh`。`test/golden/cjk_font_test.dart` 守住"汉字不是占位方块"。
- **新增中文文案后**要重新生成子集：`python tool/cjk_font_subset.py`（需要 `fonttools`），
  否则新字在黄金图里仍是方块。
