# 阅读器：模式、设置与持久化

阅读器的代码分三层，改动前先认准层，别把几何塞进 widget、也别把网络塞进页面：

| 层 | 位置 | 职责 |
|---|---|---|
| 几何（纯 Dart） | `packages/komga_reader_engine` | 单页适配缩放、双页分组与视觉顺序、纵向偏移与页码映射 |
| 编排（Flutter） | `apps/app/lib/src/screens/reader_screen.dart` | 当前页、模式解析、翻页/跳页、生命周期 |
| 编排拆件（Flutter） | `widgets/reader_layout.dart`（这一屏的派生状态：分屏、能否翻页、是否读完、页码文案）、`reader_preloader.dart`（预取调度）、`reader_progress_writer.dart`（进度防抖回写）、`reader_pages_gate.dart`（加载/失败/空书）、`reader_top_bar.dart`（顶栏接线）、`reader_frame.dart`（骨架 + chrome 显隐 + 亮度遮罩）、`volume_key_scope.dart`、`wake_lock_scope.dart` | 从 `reader_screen.dart` 拆出（UI-P0-1，行为零变化）；chrome 动画以后只改 `reader_frame.dart` |
| 绘制（Flutter） | `apps/app/lib/src/widgets/reader_{paged,vertical}_view.dart`、`reader_chrome.dart`、`reader_settings_sheet.dart` | 一屏画哪几页、顶栏底栏、设置面板 |

## 三种模式

- **单页**：一屏一页，点左右三分之一翻页，中间收 chrome；
- **双页**：`buildSpreads` 分组（封面单独、宽页单独、其余两两），RTL 时后一页画在左；
  顶栏页码显示 `2–3 / 12`；"最后一屏含末页"也算 `completed`（只按页码判断会让系列进度永远差一页）；
- **纵向连续**：`ListView` 按算好的每页高度铺开，滚动位置用 `pageAtViewportCenter`
  （视口中心法则 + 二分）换算页码；跳页用 `scrollOffsetForPage`。

## 手势、翻页方向与页码

- **键盘 / 蓝牙翻页器 / 遥控器**（UI-P3-11）：阅读器根节点 `Focus(autofocus)`；
  方向键、PageUp/PageDown、空格走和点击区同一个 `_requestTurn`，所以 RTL 下
  "右"仍是视觉上的下一页；Esc 退出。遥控器/翻页器在系统里映射成方向键或 PageUp/Down 即可。
- **缩放**：双指以**两指中点**为基准（`zoomAboutFocal` 纯函数，有单测），焦点下的画面停在原地；
  单指拖动平移，缩回适配尺寸自动归位。以前只改 `zoomFactor` 不动平移，手指在右下角捏合、
  画面却从左上角放大——这是真实反馈修掉的。
- **翻页方向**：左右三分之一的点击区与底栏两个箭头**共用同一个判断**
  （`ReaderControls.leftTurnsNext`，来源是系列 `readingDirection`）。RTL 漫画的左侧
  （点击区 / 左箭头）都是"下一页"，LTR 镜像；不会再出现"点左边前进、箭头左边后退"。
  后续加"从左到右 / 从右到左"设置时，只需要换掉这个判断的来源。
- **页码**：顶栏是"当前 / 总数"（`3 / 12`、`2–3 / 12`）；底栏只说**当前页**
  （`Page 3` / `Pages 3–4`）。底栏以前显示总页数，翻页时不变，看起来像页码坏了。
- **双击缩放**（UI-P1-6）：**只在中区**识别，双击把双击点放大到 2.5 倍，再双击还原，
  用 `gentle` 弹簧插值；放大状态下点击/音量键/箭头**默认不翻页**（先缩回再翻），
  但开启"锁定缩放"（UI-P3-4）后允许翻页，并保持缩放比例。
  中区的单击（切 chrome）要等双击判定窗口（`kDoubleTapTimeout`）过去才生效，
  左右三分之一的翻页区**不等**——为了双击把翻页拖慢 300ms 不可接受。
- 手势状态机按职责拆成三份：`reader_page_turn.dart`（翻页动画）、
  `reader_zoom.dart`（缩放/平移/点击/双击）、`reader_paged_view.dart`（布局与绘制）。

## 动态背景（UI-P1-5）

背景选"跟随画面"时，底色取**当前页边缘**的主色，翻页时交叉渐变过去：

- 提色算法在引擎里（`packages/komga_reader_engine/lib/src/edges.dart`，纯 Dart、零依赖）：
  `edgeColor(rgba, width, height, band: 2)` 只统计四边的边框带，跳过全透明像素，
  返回 `RgbColor`；双页跨页用 `averageColors` 取两页的平均。返回 null 时调用方回退黑色。
- 为什么只看页边：整页平均会被大面积的黑白框线和对话框拉偏，页边才代表"这一页的底色"。
- 解码在 `apps/app/lib/src/data/page_edge_color.dart`：`instantiateImageCodec(targetWidth: 32)`
  先降采样（引擎线程里解码），再做 O(周长) 的整数平均。**没有开 isolate**：
  一千像素的整数累加比一次 isolate 序列化还便宜，真正贵的解码本来就不在 UI 线程。
- 结果按页缓存在 `pageEdgeColorProvider`（autoDispose，跟着页图字节一起回收，
  否则读一本 200 页的书会把每一页都钉在内存里）。
- 换色只有一个 450ms 的交叉渐变层（`reader-background`），页图与 chrome 不跟着重建。
- 墨水屏：不提供"动态"选项，固定纸色（黑底会触发整屏全刷）。
- **沉浸式**（UI-P3-7）：取左右两侧页边色做双色渐变（`edgeColors`），
  双页跨页按左右位置分别平均；底色仍取两色平均，chrome 配色不变。
  它和"动态"共用提色缓存，只是多取了一份左右分侧颜色；墨水屏同样不提供。
- 配色有两个颜色域：`foreground/muted/outline` 是 **chrome** 的颜色（普通设备永远白，
  因为 chrome 永远是深色毛玻璃），`onBackground` 是直接画在阅读区底色上的文字（错误页/加载态）。

## 默认模式：跟随书

`ReaderModeChoice.auto` 是默认值：系列 `readingDirection` 为 `WEBTOON`/`VERTICAL` 时进纵向；
其余**竖屏单页、横屏自动双页**（UI-P3-3）。**双页没有元数据可依**，只能用户选，
所以模式是"偏好"而不是"每本书的属性"；用户显式选过单页/双页/纵向时，横竖屏不再改模式。

## 设置与持久化

| 项 | 行为 | 存储 |
|---|---|---|
| 阅读模式 | 全局偏好（auto/single/double/vertical） | `ReaderPrefs` JSON |
| 适配方式 | 适应屏幕 / 填满屏幕 / 适应宽度 / 适应高度；填满时溢出的方向可单指平移（UI-P1-3） | 同上 |
| 阅读方向 | 跟随系列 / 从左到右 / 从右到左；**点击区、底栏箭头、缩略图滑条、卷页方向都从这一个值派生**（UI-P1-4） | 同上 |
| 背景 | 黑色 / 白色 / 跟随画面；墨水屏不提供这一项（固定纸色，UI-P1-5） | 同上 |
| 亮度 | 阅读区上盖一层黑色遮罩（`1 - brightness`），不吃点击 | 同上 |
| 常亮 | 进阅读器置真、退出置假；见下 | 同上 |
| 跳页 | 面板里拖动，松手才跳；滑条停在目标页不回弹；纵向模式走 `jumpToken` 触发滚动 | 不持久化（临时操作） |
| 阅读预设 | 把当前这组设置命名保存（UI-P3-1），在面板顶部点一下应用、点 × 删除；应用只覆盖设置，不动预设列表 | `ReaderPrefs` JSON 的 `presets` 数组 |
| 按系列记住 | 面板开关"按系列记住"（UI-P3-2）：打开后改设置只写当前系列的覆盖，关闭删除覆盖回到全局 | 同一 JSON 的 `seriesOverrides`（ADR 0005） |
| 锁定缩放 | 翻页后保持缩放比例（UI-P3-4）；开启时放大状态也能翻页，位置回到中间 | `ReaderPrefs` JSON |

**为什么不用 Drift 存这几个字段**：它们只有几字节、写入频率是"用户改设置"，
用已有的 `flutter_secure_storage` 就够；Drift 留给真正需要查询的东西（书架缓存、页图缓存、进度 outbox）。
`ReaderPrefsStore` 是接口，将来换 Drift 实现不动调用方。

### 阅读预设（UI-P3-1）

- 预设是**快照**：模式 / 适配 / 方向 / 背景 / 亮度 / 常亮；保存时取 `ReaderPrefs.withoutPresets()`，
  预设里的 `prefs` 不再带预设（避免递归）。
- 存在同一个 `komganative.reader.v1` JSON 里（`presets` 数组），不需要新表；坏条目（缺 id/name、
  `prefs` 不是对象）逐条跳过，好的保留。
- 面板顶部：`Save current` 弹命名对话框（默认 "Preset N"），点 chip 应用，点 × 删除。
- 应用预设只覆盖配置，不覆盖预设列表；删除/保存后立即落盘。
- 没有做重命名/排序/按系列绑定（按系列见 UI-P3-2）。

### 按系列记住（UI-P3-2）

- `ReaderPrefs.seriesOverrides`：`seriesId → 纯配置`，和预设存在同一个 secure storage JSON；
  设计取舍见 [ADR 0005](adr/0005-per-series-reader-settings.md)。
- 阅读器每次渲染都用 `prefs.forSeries(book.seriesId)` 得到**生效设置**；音量键、模式、
  布局、背景全部走这一份，不会出现"面板显示系列设置、阅读区还用全局"的分裂。
- 面板开关 `reader-series-remember`：打开时把当前生效值快照成覆盖；之后改设置
  （模式/适配/方向/背景/亮度/常亮/应用预设）只写覆盖；关闭删除覆盖，回到全局。
- 全局设置本身不被系列覆盖修改；没有覆盖的系列继续用全局。
- 写入前统一 `configOnly()`（去掉 presets/overrides），JSON 不递归；坏条目跳过。
- 未做：覆盖的容量淘汰、跨设备同步（同全局偏好，都是本机设置）。

### 锁定缩放（UI-P3-4）

- 设置里打开后，翻页保留 `_zoom`；`ReaderPagedView.didUpdateWidget` 在换屏时
  只把 `_pan` 归零（上一屏的平移区间未必还成立），不调用 `_resetZoom`。
- 放大状态下 `turn()` 默认直接 return；开启锁定后放行，否则"锁定缩放"永远走不到翻页。
- 适配方式/单双页变化仍然复位缩放——旧比例对应的是旧布局，保留只会错位。

### 手动修正双页分组（UI-P3-5）

- 引擎 `buildSpreads(groupFrom:)`：`groupFrom` 之前的页保持自动分组，从这一页
  （0 基）开始按同样的宽页规则重新两两配对；`groupFrom` 落在默认跨页中间时，
  前一页单独留下；宽页仍单独成屏。
- 入口：双页模式下打开缩略图网格（顶栏网格按钮），**长按某一页** = "从这一页开始分组"；
  再长按同一页恢复自动。底部滑条也支持长按，但它是按"屏"分组的，语义是"从这一屏第一页开始"。
- 当前只在本次阅读会话内有效（`ReaderScreen._spreadFrom`），不落盘；
  重启后回到自动分组。要持久化需要按书存 offset，留到有需求再做。
- 长按有 selection 触感；SnackBar 反馈"从第 N 页开始分组 / 恢复自动分组"。

### 分享单页（UI-P3-6）

- 长按底部缩略图会弹一个动作面板：**分享此页**；双页模式下同时有"从这一页开始分组"
  （P3-5 的入口从"长按直接分组"改成菜单，避免两个动作抢同一个手势）。
- 分享实现：`data/page_share.dart` 取页图字节 → 写临时目录 PNG →
  `share_plus` 调系统分享面板；用户可以在面板里选消息/笔记/邮件，或"存储到文件"。
- 测试用 `ReaderScreen.onSharePage` 接缝（生产不传），不真正打开系统面板；
  插件本身靠模拟器/真机走查。选型与代价见 [ADR 0006](adr/0006-share-page-with-share-plus.md)。
- 分享失败（页图错误/平台异常）只弹 SnackBar，不影响继续阅读。

### 自动去白边（UI-P3-10）

- 设置面板开关"自动去白边"；开启后每页解码到 48px，检测四周连续纯色（白/黑）边框，
  再按比例裁掉。检测是纯函数 `detectBorderCrop`（`komga_reader_engine`），有单测覆盖
  白边/黑边/不对称/无边框/整页纯色/四角不同。
- 绘制用 `MemoryImage` 的 ImageStream 拿已解码位图，`drawImageRect` 只画中间区域；
  不自己做第二套图片解码，也不改服务端请求。检测失败一律按"不裁"处理。
- 限制：单边最多裁 40%，四边加起来会把整页裁空时放弃；只处理纯色边框，
  渐变/花纹边框不动。开关按系列记忆（UI-P3-2）与预设（UI-P3-1）都会带上。

### 隐身模式（UI-P3-12）

- 顶栏眼睛图标切换；**本次阅读**不回写进度（`_scheduleProgress` 与生命周期 flush
  都被 `_incognito` 短路），也不落盘，退出阅读器自动恢复。
- 不发请求、不写 outbox；已经写过的进度不撤销。SnackBar 明确提示"本次不保存进度"。
- 与 Panels 的语义不同：Panels 是"会话记录但不出现在 Reading Now"，
  我们是"这次阅读完全不写回 Komga"，因为服务端没有 hidden 标记。

坏存档必须回默认值（`ReaderPrefs.fromJson` 逐字段判类型 + 夹取），
亮度下限 0.2：存档里出现 0 也不能变成黑屏。

## 页图加载与预取（翻页不闪黑）

页图有三层，翻页走的是前两层，第三层只在**离线**时兜底：

| 层 | 内容 | 生命周期 |
| --- | --- | --- |
| `readerPageImageProvider` | 当前屏的原始字节（`AsyncValue`） | autoDispose：翻走即释放 |
| `KomgaReaderRepository._pages`（`ByteLruCache`） | 最近 16 页的原始字节 | 会话内，LRU |
| `PaintingBinding.imageCache` | 解码后的位图（`MemoryImage`） | Flutter 引擎管，默认 100 MB |
| `DriftHttpCache` | 磁盘上的响应体 | 只在请求**失败**时读（`KomgaSession._cachedBytes`） |

第三层是"断网还能翻回去看"，不是读穿缓存：**在线时 LRU 未命中的页仍会请求网络**。

**第一帧的字节不许等异步**：`ReaderPage` 先用 `ReaderRepository.cachedPageImage`
同步问一句"这页现在在不在内存里"，在就直接画（翻回去、预取过的页都是这条路径）。

为什么必须同步：provider 是 autoDispose 的，每换一页都会先给一次 `AsyncLoading`，
只等它的话第一帧就是"黑底 + 转圈"——用户看到的就是"翻页闪一下"。
这一条是踩过的坑：先把 provider 改成 autoDispose（为了不把整本留在内存里），
结果**连翻回去都开始闪**，因为旧的 provider 不会 dispose、恰好白拿了"首帧就有数据"；
补上同步查询后才两边都对，并钉了「翻页首帧」两条测试（只 `pump()` 一帧断言）。

真没加载好的页（LRU 里没有）：**黑底 + 转圈**。

试过"先继续画上一页"（把旧画面顶到新页解码完），反馈很难受：
页码变了、图没变，用户第一反应是"卡住了/是 bug"。所以宁可露出明确的"还没加载好"。
预取做深就是为了让这条路径尽量不出现（见下）。

预取（`apps/app/lib/src/widgets/reader_preloader.dart` + `komga_reader_engine/src/preload.dart`）：

- 计划按**屏**算（`preloadPlan`），不是 `page ± 1`。双页模式一屏两页，按页码加减会
  一直漏掉每屏的第二页，表现是"翻一屏闪一次、翻一页不闪"——很难查，所以钉了单测；
- 往前 **4 屏**、往后 **2 屏**抓字节（单页约 4 页 / 双页约 8 页），
  最近 **2 屏**额外 `precacheImage` 预解码；
  按 1 页/秒的阅读速度算，4 屏就是 4 秒以上的缓冲——阅读快的人不会翻两下就撞上转圈；
- 触点在 `build` 里（`_schedulePreload`），只在 **页码或模式变化**时排一次，下一帧执行：
  保证当前页自己的请求先出去（弱网下顺序就是优先级），也避免每帧重复排；
- 并发上限 4 张，其余**排队**（`ReaderPreloader._pump`：前一张回来就补下一张）。
  早先是"超上限直接丢"，阅读快时计划尾部永远轮不到——排队才对；
- **为什么光抓字节不够**：`Image.memory` 在解码完成前那一帧没有像素，看到的就是
  Scaffold 的黑底——这就是"闪一下黑"。预解码后翻过去首帧就有图；
  解码比抓字节浅一档，是因为一张 1500×2200 的页解出来约 13 MB，全部预解码会把
  默认 100 MB 的 `ImageCache` 挤爆；
- 纵向模式不在这里预取：`ListView.cacheExtent` 自己会建下面两屏，再叠一层是重复请求；
- 预取失败静默——真翻到那页时会重新请求并显示正常的错误/重试。

验证方式：`packages/komga_reader_engine/test/preload_test.dart` 钉计划；
`apps/app/test/reader_screen_test.dart` 的「页图预加载」组断言"翻过去之前请求过哪几页/几屏"
（`FakeReaderRepository.pageRequests`），并用 `runAsync` 放真实时间断言下一屏已进 `ImageCache`；
「翻页首帧」组只 `pump()` 一帧，断言第一帧里没有 `CircularProgressIndicator`、
`reader-image-*` 已经在了（`pumpAndSettle` 会把这种问题吞掉，别用它验闪烁），
其中一条用 `FakeReaderRepository.pageGates` 把页图请求挂住，验证冷页确实显示转圈。

## 翻页动画（卷页）

跟手卷页：手指横滑时纸跟着卷起来，松手补完；点击/底栏箭头/音量键走同一套动画。
往前翻卷走当前页，**往回翻把上一页从书脊外卷回来**（同一条路径倒放，严格对称）。

### 模型：圆柱卷页（`packages/komga_reader_engine/lib/src/page_turn.dart`）

纸被"捏住的角" `C`（RTL 左下角；LTR 镜像为右下角）拖到手指 `F`，沿一根半径 `R` 的圆柱卷过去：

```text
         ┌──────────── 卷过去平压的部分（背面朝上）
        ╭╯
       (   圆柱：下半圈正面，上半圈背面
        ╰╮
────────┘ 还平铺在原位的部分（正面）        u →（指向被捏住的角）
         ↑ 轴线 A
```

- 卷曲方向 `u = normalize(C − F)`，轴线垂直于 `u`；
- 轴线位置是闭式解：角卷过半圈后平压下来要正好落在手指上，`|F − C| = 2a − πR`，
  所以 `a = (|F − C| + πR)/2`，`A = C − u·a`。单测直接钉这个不变量；
- **折线倾角不是参数**：手指往上走折线就斜，水平拖折线就竖，完全由 `F` 决定；
- 半径 `R = curlRadiusFor(|F − C|)`：起手趋于 0（只翘起一个页脚），在 `4·R_max` 处平滑饱和；
  起手不归零的话 `a = πR/2 > 0`，手指没动角就已经卷起（跳变）；
- 约束（`constrainFinger`）：手指不低于底边、`u` 倾角不超过 `kCurlMaxTilt`（≈52°），
  否则卷起的是整条左边，像撕纸；
- 全部手感参数：`kCurlRadiusRatio`（最大半径 / 页宽）、`kCurlArchRatio`（自动翻页路径的拱起）、
  `kCurlMaxTilt`。调只改这里。

### 双页：铰接在书脊上（`solveCurl(hinged: true)`）

双页模式下以两页之间为书脊，**掀起那一侧的半页**（RTL 左半、LTR 右半）翻过去盖住另一半，
纸背就是下一屏落在另一半的那页——完全模拟翻书。核心模型不变，只多两条约束：

- **书脊钉死**：轴线不得越过书脊，`d(书脊两端) ≤ 0`，即 `a ≤ −max((S − C)·u)`。
  被夹住时纸长不够平压到手指，`F` 改由 `a` 反推（`|F − C| = 2a − πR`）；
- **落地时半径收成 0**：终点是角落到另一半页的对应角 `(2·width, height)`（`curlTravel = 2·width`），
  此时纸恰好沿书脊镜像、背面和下一屏的那页严丝合缝。`R > 0` 时平压部分会差出 `πR`，
  所以半径按 `t(2 − t)` 在落地前 `4·R_max` 内收拢（斜率连续为 0，无折点）。

一次翻页因此分前后两段：前半段从角上卷起、向书脊推进；后半段越过书脊，半径收拢、平落在另一半上。
往回翻同样是倒放：上一屏的那半页从另一半上掀起、翻回来。

图层（`reader_curl_plan.dart` 的 `_CurlPlan`，把"翻之前的屏 A / 翻之后的屏 B"统一起来）：

| | 卷的纸 | 纸背 | 垫在下面 |
| --- | --- | --- | --- |
| 单页 | A 那页 | 白纸 + 透印 | B 那页 |
| 双页 | A 掀起侧的半页 | B 落地侧的那页（沿书脊镜像采样） | B 掀起侧 + A 落地侧 |

着色器里纸背是 `uBack` 在镜像点 `(2·spineX − q.x, q.y)` 处的像素（`uHasBack = 1`），
纸背那页落地后的矩形是 `uBackRect`——两页宽度不同也能对上。

单页↔双页交界（封面单独一屏 → 第一个跨页）页数不配对，这一下仍然走平移。

### 手指运动（`curl_motion.dart`）

动画的状态是**手指位置**，不再是一个 0..1 进度驱动一堆人工曲线：

- **自动翻页**：手指沿底边推进、中途向上拱起（`kCurlArchRatio`·页宽），折线先斜后竖；
  终点让圆柱完全滑出**屏幕**另一侧（`curlTravel`，不是只滑出纸面，否则窄页收尾会剩一根白柱）；
- **往前拖**：角就在手指下面，位移直接加在角上（纵向也算）；
- **往回拖**：上一页的角在屏幕外，从路径终点往回退同样的距离，叠加纵向位移；
- **松手补完**（`settleFinger`）：从松手处直线走到目标，再叠上"路径相对自身弦的拱起"；
  点击翻页时起点就在路径上，因此完全沿拱形走；拖一半松手也不会跳。
  控制器每次都从 0 播到 1，起点单独记录——"翻了 70% 一松手跳回 0 重播"从结构上不可能发生。

松手判定仍按"横向拖动距离 / 视口宽"（`_progress`）走 `settlePageTurn`：拖过 35% 或轻扫就补完。
注意它和手指位置是两回事：整张纸翻走手指要走约两倍页宽，不能拿手指位置判定。

### 渲染（`apps/app/shaders/page_curl.frag`）

每个像素算 `d = (p − A)·u`，**逆映射**到纸面点 `q`，从下往上合成：

| 层 | 条件 | 纸面点 `q` | 画什么 |
| --- | --- | --- | --- |
| 平铺正面 | `d ≤ 0` | `p` | 当前页 + 接触阴影 + 翻过去那半张纸投下的影子 |
| （露出的下层） | `d > 0` 且无纸 | — | 透明 + 卷筒投在下层的影子 |
| 圆柱正面 | `0 ≤ d ≤ R`，`θ = asin(d/R)` | `p + u(Rθ − d)` | 正面图像 × 法线漫反射 |
| 圆柱背面 | 同上，`θ = π − asin(d/R)` | 同上 | 纸背 × 漫反射 + 高光 |
| 翻过去的背面 | `d ≤ 0` | `p + u(πR − 2d)` | 纸背（单页白纸 + 7% 透印；双页是下一屏的那页） |

> **明暗一律"相对平铺纸面"**：θ = 0 和 θ = π 处亮度都恰好是 1，所以各层在轴线（`d = 0`）
> 处硬切也看不出缝。第一版用绝对光照，再在轴线两侧各做半像素过渡，斜向（45°）翻页时轴线上
> 透出一条细亮线（"高亮虚影"），而且卷筒两端是一条"灰 | 白"的硬斜边。
>
> **阴影跟真实剪影走**：卷筒投到下层的影子，按"这条垂直于轴线的线上卷起来的纸实际伸到多远"
> 计算（`silhouetteAt`：射线与纸面矩形求交），沿轴向取 5 个样本做软边。早先只看 θ = π/2
> 处有没有纸，角附近纸其实卷不到 90°，影子就被截成一条亮斜带。翻过去那片纸的影子
> 在 `d > 0` 时按 `d = 0` 取值并延续到圆柱正面，跨过轴线时是连续的。

每层都由同一套参数化推出，纸面天然连续；"在不在纸上"都用 1px 覆盖率做抗锯齿。
只有一个出口（flutter issue 190809：带 sampler 的 main 多 return 在 Windows 上可能编不过）。

逐帧基线在 `apps/app/test/golden/page_curl_golden_test.dart`（合成网格位图，能直接看出纹理有没有被拉伸/翻转）：
起手、中段、收尾、往回翻中段、书脊在左的镜像；双页（平板横屏，纸背用黄底网格以便区分）：
掀起、越过书脊、即将落地、书脊在左的镜像。

### 位图（`CurlSheets`，`widgets/page_curl.dart`）

- 空闲时**并发**解码**当前屏 + 前后相邻屏**（单页最多 3 张、双页最多 6 张），
  直接从 `spread` / `nextSpread` / `previousSpread` 取页集，不依赖视口或 `_planFor`
  （封面/宽页等 1↔2 边界也会提前把下一屏解好）；单页解码慢或失败不阻塞同批其余页；
  翻过去后仍然需要的位图直接复用，不重新解码；
- 换掉的位图延迟一帧释放；重复预加载合并同页的在途解码，不替换正在借用的位图。
  切出卷页模式或换书时调用 `clear()` 立即作废在途解码并延后释放；切回卷页模式时
  `didUpdateWidget` 立即重新排解码，不需退出重进；
- 翻动开始时定下"这次卷不卷"（`_plan`，判定用 `_CurlPlan.requiredPages`）：
  **只要求当前被掀起来的那一页/半页就绪**（单页看 `sheetPage`，双页往前翻看当前屏掀起侧
  `sheetPage`、往回翻看当前屏落地侧 `backPage`）；途中位图到了会自动在下一帧显示，
  不切换动画模式。相邻屏还没加载完时，底层由 `ReaderPage` 露出加载态，着色器缺失的那一面
  暂用白纸（`uHasSheet` / `uHasBack`），落地帧 `r = 0` 仍按 `uHinged` 正常绘制。

**冷页交接不能只看字节缓存**：卷页的 `ui.Image` 和 Flutter `Image.memory` 的解码缓存
是两条独立路径。纸背已在着色器里显示，不代表落地后新挂载的 `Image.memory` 已有首帧；
两者之间曾出现右半页短暂全黑。`ReaderPage.decodedImage` 借用同一页的卷页位图：
`frameBuilder` 在普通图片首帧未返回时画该位图，首帧就绪才交给普通图片。
底层页同样借用已解码位图。这里使用的是**同一目标页**，不是拿上一页顶替，也不靠延时等待。

回归测试 `apps/app/test/golden/reader_curl_handoff_golden_test.dart` 清空 Flutter `ImageCache`，保留卷页位图，
分别检查 RTL/LTR 的往前、往回交接首帧像素（不能用 `pumpAndSettle` 吞掉空窗），并保存
4 张 `reader_curl@tablet_dark_*_handoff` 黄金图，同时验证双页下一屏冷页时仍照常铰接卷页并露出加载态；
`reader_turn_test.dart` 覆盖单页/双页相邻屏未就绪照常卷页、当前页失败退化平移、以及阅读中从平移切换卷页立即生效；
单页的视觉由 `reader_curl_cold_under_golden_test.dart` 的两张黄金图钉住
（`reader_curl@tablet_dark_cold_under_mid`：纸真在卷；`..._reveal`：卷走之后露出加载态）；
`curl_sheets_test.dart` 覆盖在途解码合并、并发不互堵、保留/释放、`clear()` 与过期结果。

> **踩过的坑**：第一版用 `RenderRepaintBoundary.toImage()` 截当前屏当"这张纸"。
> 本地 widget 测试能跑通，真机上 `toImage` 永远拿不到 layer（`Null check operator
> used on a null value`），滑动翻页直接没有任何反馈。改成从页图字节自己解码后一次通过。
> 结论：截图类 API 必须真机验证，`pumpAndSettle` 绿了不代表设备上能用。

> **上一版为什么推倒重来**：之前用一个 0..1 进度驱动倾角、半径、锥度、弯曲角等
> 互不约束的人工曲线（折页 → 连续曲面 → …），每修一个症状就加一个参数；
> 手指的纵向位置也完全没用上。圆柱模型只有一个状态（手指位置）和一个闭式解，
> 各层由同一参数化推出，不再需要这些补丁。

**手势与判定**（`widgets/reader_paged_view.dart`，翻页状态机在 `reader_page_turn.dart`）：

- 单指、未缩放、`|dx| > 14px` 且横向占优（`|dx| > |dy| * 1.4`）才进入拖拽；
  双指一旦出现就标记为缩放，本次手势不再翻页；
- 动画期间忽略新的点击/拖动（`_TurnPhase != idle`）。

**回退与不做动画的场景**：

| 场景 | 行为 |
| --- | --- |
| 单页模式、往前翻 | 卷走当前页 |
| 单页模式、往回翻 | 上一页从书脊外卷回来 |
| 双页模式 | 掀起侧半页铰接在书脊上翻过去，纸背是下一屏的那页 |
| 单页↔双页交界（如封面 → 第一个跨页） | 平移 |
| 单页：纸面位图还没解码好（当前页 / 上一页） | 本次平移 |
| 单页：底层相邻页还没解码好 | 照常卷页，掀开后露出它的加载态 |
| 双页：当前屏被掀起的那半页位图还没解码好 | 本次平移 |
| 双页：相邻屏（纸背 / 底层）还没加载好 | 照常铰接卷页（纸背暂用白纸、底层露出加载态） |
| 墨水屏 / 系统"移除动画" | 不做动画：点击瞬切，横滑不响应 |
| 着色器加载失败 | 平移（不报错） |

**已知边界**：

- 着色器在 Windows 黄金图上是 Skia、真机上是 Impeller，像素级会有细微差异；
- 单页模式纸背是"白纸 + 透印"（单页模式下纸背本来就该是空白）；双页才用真实页面。
- 双页的两页高度不同时，每页按自己 contain 后的矩形卷/采样（和屏幕上的图严格对齐）；
  纸背沿书脊镜像到落地页的矩形，翻动途中纸面与纸背的上下边会差出两页的高度差，落地那一帧是对的。

## 缩略图跳页

- 顶栏的网格按钮打开缩略图面板（`widgets/page_navigator_sheet.dart`），当前页描白边；
- Komga **没有页级缩略图接口**（`/books/{id}/thumbnail` 是整本封面），所以缩略图就是页图本身：
  网格懒构建 + `cacheWidth: 240` 解码降采样，只有滚到的页才会下载；
- 点一张 = 走和设置面板跳页同一条路径（纵向模式也会滚过去）；
- 黄金图 `reader_pages@phone_dark`：缩略图是**真实异步解码**，基线要在 `act` 之后
  放一小段真实时间（`settleAfterActWithRealTime`），否则截到的是黑块（踩过）。

### 底栏横向滑条（UI-P1-2）

chrome 打开时，底栏上方还有一条横向缩略图滑条（`widgets/reader_thumbnail_strip.dart`）：

- **按屏分组**：双页模式一条代表一跨页（`ReaderLayout.screenAt`），和翻页粒度一致；
- **懒加载**：`ListView.builder` + 固定 `itemExtent`，只有可见范围内的实例会构建，
  也才会去请求页图字节（60 页的书打开时不会把整本拖下来，有测试钉住）；
- **自动居中**：当前屏的缩略图滚到视口中间；翻页 / 跳页 / 切模式都会重新居中；
- **方向**：RTL 用 `reverse: true`，第一页在最右，与点击区、底栏箭头同向；
- **触感**：拖动时每经过新的一屏给一次 `AppHaptics.selection()`（受"触感反馈"开关控制）；
- **拖管的降采样**按 `缩略图宽 × DPR` 解码（不是 240），避免一屏十几张原图解码；
- 占位**不转圈**：一屏十几个转圈既吵又会让 `pumpAndSettle` 永不静止（踩过，
  整组测试挂住），所以未就绪时是一个静态的小方块。
- 网格面板**保留**：滑条用于邻页微调，网格用于跳到远处。

## chrome 显隐与沉浸模式（UI-P1-1）

- chrome（顶栏 + 底栏，含书末卡片与缩略图滑条）是**浮层**，阅读区固定按全屏布局；
  早先 chrome 占 `Column` 的行，一隐藏画面就变大，"点一下中间图会跳"（有测试钉住尺寸不变）。
- 显隐动画：淡入淡出 + 上下 8px 位移，时长取 `AppMotion.standard`；动画结束用 `Offstage`
  把 chrome 从画面与点击树里摘掉（不销毁，滑条的滚动位置留着）。
- 系统栏同步：chrome 隐藏 → `immersiveSticky`，显示 → `edgeToEdge`；
  切换在**帧后**发平台调用，避免 MediaQuery 同帧变化让 chrome 跳一下；
  退出阅读器一定恢复（`widgets/reader_system_ui.dart`）。
- chrome 的内边距用 `MediaQuery.viewPadding`（系统栏隐藏时不变），不是 `padding`。
- 墨水屏 / 系统"减少动态效果"：瞬切，无位移。

## 书末：下一本 / 回系列

读到最后一页（双页模式：最后一屏含末页）时，底栏上方出现一张**书末卡片**
（`widgets/reader_finished_card.dart`，UI-P1-7）：下一本的封面、书名、卷号，
主按钮"继续阅读"、次按钮"返回系列"，入场是淡入 + 上浮。

- **下一本**：按系列书列表的顺序取下一本；点它 = `pushReplacement` 打开。
  用替换而不是压栈：连读十本不必按十次返回，书架层级始终是"系列 → 当前这本"。
- **在书尾继续往前翻**也会直接进下一本（Panels 的行为）；往回翻不会触发。
- **Series**：退回系列详情。
- 拿不到下一本（已是最后一本 / 离线没缓存 / 系列超过 100 本）时只显示 `Finished` 一行，
  **不报错**——"下一本"是锦上添花，不能因为它把读完的页面变成错误页。
- 完成判定同时用于进度回写，所以"看到卡片"与"服务端 completed=true"是同一个条件。

## 硬件键：音量键翻页

`HardwareKeys`（`packages/komga_platform/lib/src/hardware_keys.dart`）把原生音量键变成
`Stream<PageTurnKey>`；阅读器 `initState` 订阅、`dispose` 取消：

- 音量上 = 上一页，音量下 = 下一页（阅读顺序，不跟 RTL 反转）；双页模式按"一屏"翻；
- 纵向连续模式忽略按键，滚动仍交给 `ListView`；
- Android 在 `MainActivity.dispatchKeyEvent` 里消费 ACTION_DOWN（系统音量不再变化）；
  iOS/桌面没有实现，`MissingPluginException` 静默降级为空流。

实现边界、事件消费的全局副作用与验证状态见 [docs/a11y-and-input.md](a11y-and-input.md)。

## 屏幕常亮

`packages/komga_platform/lib/src/wakelock.dart` 走 `komganative/device` 通道，Android 侧在
`MainActivity.kt` 只加一个 `FLAG_KEEP_SCREEN_ON`。故意没引 `wakelock_plus`：
需求就是一个 flag，加插件等于多一层原生构建面。

- iOS：**未实现**（`MissingPluginException` 被静默吞掉，只是不常亮，不影响阅读）。

## 已知缺口

- 亮度是**应用内遮罩**，不改系统亮度（系统亮度需要新插件；遮罩已能满足"夜里不刺眼"）；
- 偏好是全局的，不按书记忆（按系列记忆见 `docs/ui-polish-plan.md` 的 UI-P3-2）；
- 纵向模式不叠加缩放（交给滚动），也不跟"适配方式"；
- 动态背景第一版只有单色：多色的"沉浸式渐变"排在 UI-P3-7；
- 分页模式只预取前面 4 屏 / 后面 2 屏，**不预下载整本**（离线整本阅读靠"下载"功能，不靠预取）；
- 在线时页图只要不在 16 张 LRU 里就要重新请求网络（磁盘缓存是离线兜底，不是读穿缓存）；
  这种"很远的回翻"不会黑屏（会先画上一帧），但会明显停一下。
- 预解码依赖默认 100 MB 的 `ImageCache`：普通扫描页（约 1000×1400 ≈ 5.6 MB）装得下十几张，
  但超大页（解出来 > 30 MB）会把预解码的那张挤出去，翻页仍可能闪一次——真遇到了再按需
  放宽预算或降采样，别一上来就动全局参数。
