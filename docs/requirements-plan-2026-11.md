# 差距收敛需求清单与开发计划（2026-11）

> **输入**：[competitor-research-2026-11.md](competitor-research-2026-11.md)（Panels 3.13.11 / Aidoku v0.9-4 / 本仓库 `bffa164`）。
> **规划口径**：1 人 + Agent，每周 5 个工作日；估时已含单测/黄金图/文档，**不含** 20% 缓冲。
> **估时**：S ≤ 1 天；M = 2–3 天；L = 4–5 天；XL > 1 周。
> **优先级**：P0 = 正确性/信任，必须先清；P1 = 日常高频、直接对标；P2 = 深度/差异化，可顺延；P3 = 明确不做。
> **原则**：先修“文档说有、代码没做到”，再加新功能；每个需求独立可验收，不把多个功能塞进一个 PR。

## 0. 计划总览

### 0.1 目标

把报告里的差距收敛成 **45 项需求**，分 7 个迭代；**总估约 80–85 人日**（含单测、黄金图、文档、设备走查），不含 20% 缓冲。

| 阶段 | 周期 | 目标 | 需求数 | 出口 |
|---|---|---|---|---|
| W0 正确性 | 2 周 | 现有功能可信：墨水屏、持久化、方向、预设、加载态、列表进度 | 9 | 可发布一个“修 bug”版本 |
| W1 阅读器 | 2 周 | 页码滑杆/剩余页、目录、AA、设置分组、动画、分组持久化 | 7 | 阅读器日常体验接近 Panels |
| W2 书架/系列 | 2–3 周 | 标题/筛选状态、多选、置顶、书列表排序、系列批量/下载全部 | 8 | 长系列“找下一本”闭环 |
| W3 搜索/下载/设置 | 2 周 | 搜索历史、facets、分页、下载设置、队列 UI、设置 IA | 6 | **MVP 完成（约 8–9 周）** |
| W4 历史/收藏/备份 | 2 周 | session 模型、History 骨架、最近阅读、收藏集封面、本地备份 | 5 | 有“时间维度”的底座 |
| W5 深度/平台 | 2 周 | Insights、平板两栏、iPad 阅读布局、数据层 i18n、a11y | 6 | 完整度接近竞品 |
| W6 可选增强 | 1–2 周 | 点击区、自动滚动、收藏集 CRUD、语言扩展 | 4 | 按需裁剪 |

- **MVP = W0–W3**：约 **8–9 周**（W2 视溢出占 3 周）。
- **完整版 = W0–W6**：约 **14–16 周**；如果 Agent 能并行测试/黄金图/独立模块，可压到 **11–12 周**；单人无 Agent 建议按 **17–18 周** 排。
- W4 的平板两栏是 L；若溢出，顺延 1 周，G3 相应后移，不压缩测试。
- W6 可根据用户反馈裁剪；W0–W2 不建议裁剪。
- 每个迭代结束都跑一次完整门禁，不攒到最后。

## 2. 详细需求与验收

### 2.1 P0：正确性（W0）

#### FIX-01 墨水屏探测贯通阅读器

- **现状**：`app.dart` 用 `forceEink || detected` 选主题；`reader_screen.dart:341` 只读 `forceEink`。自动探测的机型仍黑底、深色 chrome、卷页、动态背景。
- **需求**：新增单一 `effectiveEinkProvider`（`forceEink || detected`）；`ReaderPalette`、阅读器动画、背景选项、卷页效果全部读它；e-ink 强制白底、瞬切、无阴影、隐藏动态背景。
- **验收**：
  - 模拟 `detectedEink=true`（不打开强制开关）时，阅读器白底、无卷页、无动态背景。
  - 强制开关与自动探测行为一致；普通设备不受影响。
  - 新增 `reader_auto_eink` 黄金图；provider/reader 单测。
- **估时**：S（0.5–1 天）。

#### FIX-02 主题/墨水屏/书架视图持久化

- **现状**：`settings_store.dart` 只存语言/触感；主题、强制墨水屏、书架视图/排序/筛选/封面档位重启回默认。
- **需求**：扩展设置存储（JSON blob，容错读）；持久化 `themeMode`、`forceEink`、`shelfView`、`coverSize`、`sort`、`readStatus`；`libraryId` 按服务器分 key，避免切服务器串数据。
- **验收**：
  - 冷启动恢复上次主题、墨水屏开关、书架视图/排序/筛选。
  - 切换服务器不携带上一台的库筛选；坏存档回默认。
  - 单测覆盖缺字段/未知枚举/非法类型。
- **估时**：S（1 天）。

#### FIX-03 阅读方向覆盖所有入口

- **现状**：`search_screen.dart:142`、`readlist_detail_screen.dart:77` 只传 `ReaderArgs(book)`，`direction` 默认 unknown；RTL 书按 LTR 打开，点击区/箭头全反。
- **需求**：`ReaderArgs` 增加 `seriesId`（或由阅读器内部按 `book.seriesId` 查方向）；`ReaderScreen` 在 `direction == unknown` 时从 `seriesDetailProvider` 解析；深链同样兜底。
- **验收**：
  - 从书架、搜索、阅读列表、深链进入同一本 RTL 书，方向一致。
  - 方向未知且系列查不到时回 LTR，不阻塞打开。
  - 导航/reader args 测试。
- **估时**：S（0.5–1 天）。

#### FIX-04 预设应用补齐锁定缩放/去白边

- **现状**：`reader_prefs_provider.dart:105-113` 全局应用只复制 mode/brightness/keepAwake/fit/direction/background，漏 `lockZoom`/`trimBorders`；系列覆盖路径却完整。
- **需求**：全局应用与系列覆盖共用同一个 `applyConfig`，保证字段完整；新增“预设快照 == 应用后配置”的往返测试。
- **验收**：
  - 保存含锁定缩放/去白边的预设，应用到全局后两项一致。
  - 应用到系列覆盖同样一致；删除覆盖回全局。
  - 单测覆盖旧存档缺字段。
- **估时**：S（0.5 天）。

#### FIX-05 正在读骨架与空态修正

- **现状**：`reading_now_screen.dart:36` 用 `ondeck.value ?? []`，加载中先渲染 “Nothing in progress”，数据回来再跳。
- **需求**：按 `AsyncValue` 的 loading/hasError/value 分支；加载中显示继续卡骨架 + 货架骨架；错误只在有旧数据时底部提示，不清空；确认无数据才显示空态。
- **验收**：
  - 冷启动/刷新不闪空卡；失败保留旧内容；首次失败显示错误态但可重试。
  - widget 测试（延迟 provider）+ 黄金图。
- **估时**：S（0.5–1 天）。

#### FIX-06 列表层进度与系列名

- **现状**：`series_book_row.dart` 只显示 `19 pages` / `Read · 20 pages`；继续阅读卡显示 `book.name`（“Vol. 1”），没有系列名；搜索书结果没有系列上下文。`Book` 领域模型未保留 `seriesTitle`（Komga `BookDto` 有）。
- **需求**：
  - 领域层 `Book` 增加可选 `seriesTitle`，解析 fixture 的 `seriesTitle`；`withProgress` 保留。
  - 书行 subtitle：`p. 5/12 · 24 pages`；完成态 `Read · 24 pages`；未读 `24 pages`。
  - 继续阅读卡：第一行系列名，第二行 `Vol. 1 · p. 5/12`。
  - 搜索结果书行：`系列名 · 书名`。
- **验收**：
  - `book_in_progress.json` / `books-search.json` 解析出 `seriesTitle`。
  - 上述三处 UI 文案与黄金图更新；无系列名时回退书名。
  - 单测 + widget 测试。
- **估时**：M（2 天）。

#### FIX-07 下载队列持久化

- **现状**：`download_providers.dart:94-97` 队列/在途只在内存；杀进程后“排队中”消失，已下载记录仍在。
- **需求**：把 queued/active 状态落 Drift（bookId、状态、创建时间、进度页）；启动时恢复队列，跳过已下载/已删除书；提供“取消全部/继续”语义；不重复入队。
- **验收**：
  - 杀进程重启后队列恢复或明确取消，不出现幽灵“下载中”。
  - 已下载书不入队；删除书自动清队列。
  - 单测（状态机/重启恢复）。
- **估时**：M（2–3 天）。

#### FIX-08 搜索/收藏集/阅读列表分页

- **现状**：`library_repository.dart` 已支持 page/size 与 `PageResult.totalElements`，但 UI 固定取 20 条；第 21 条起静默消失。
- **需求**：搜索（系列/书）、收藏集、阅读列表全部接分页/无限滚动；底部显示“还有 N 条/加载更多”；失败保留已有内容；请求竞态用 generation 保护。
- **验收**：
  - 25+ 条结果能继续加载到全部；总数与 UI 一致。
  - 快速切换查询不串结果；失败不清空。
  - repository/controller/widget 测试。
- **估时**：M（2–3 天）。

#### FIX-09 版本号/简介按钮/标签溢出

- **现状**：`settings_screen.dart` 版本硬编码 `0.1.0 (v1)`；`series_header.dart` 简介无论长短都显示 “Show more”，标签 `take(4)` 无 `+N`。
- **需求**：版本/构建号读 `package_info_plus`；简介用 `TextPainter` 或 `LayoutBuilder` 判断是否真的溢出；标签溢出显示 `+N` 并可展开/查看全部。
- **验收**：
  - 设置页版本=构建版本；短简介不显示按钮；5+ 标签显示 `+N`。
  - widget 测试 + 黄金图（settings/series）。
- **估时**：S（1 天）。

**W0 出口**：以上 9 项全绿；`dart run tool/ci.dart check`；`ci.dart install` 在模拟器实际走查：e-ink 自动探测、重启持久化、搜索进 RTL、预设、正在读、队列、分页、版本号。

### 2.2 P1：阅读器（W1）

> 先做 **QUA-01**（拆 `reader_screen`），再加滑杆/目录，否则 487 行会继续膨胀，违反 350 行约定。

#### RDR-01 页码滑杆 + 剩余页

- **需求**：底部新增滑杆（当前页/总页/剩余页），支持拖动跳页、点击轨道、RTL 方向、触感；移除顶部/底部重复页码；`Semantics` 播报“第 x 页，共 y 页，剩 z 页”。
- **验收**：单页/双页/纵向（纵向可用比例）；RTL 滑杆方向正确；拖动不误触翻页；黄金图 `reader@phone_dark`、`reader_double`。
- **估时**：M。

#### RDR-02 目录/章节列表

- **需求**：阅读器顶栏加“目录”，打开系列书列表；当前书高亮，显示已读/未读/页码；点击切换用 `pushReplacement`，保留阅读方向/预设；书末仍保留下一本卡片。
- **验收**：20+ 本系列能滚动定位当前书；切换后进度写入正确书；返回栈不堆积；黄金图。
- **估时**：M。

#### RDR-03 顶栏 IA + AA 快捷设置

- **需求**：顶栏收成 4 个槽位：`X`、标题、`AA`（快捷设置）、`...`（目录/隐身/网格/模式/分享）；`AA` 打开底部快捷面板：亮度、背景、方向、适配、锁定缩放。
- **验收**：调整亮度/背景无需进完整设置；隐身/网格仍可达；黄金图；a11y 标签。
- **估时**：S–M。

#### RDR-04 阅读设置分组/重置/适配预览

- **需求**：分四组（页面/布局/颜色/交互）；每组可重置；适配方式用 4 个小示意图；顶部显示当前模式摘要；小屏不出现超长单列。
- **验收**：四组均可用；重置只影响本组；示意图在 e-ink 为线框；黄金图。
- **估时**：M。

#### RDR-05 翻页动画选择

- **需求**：`PageTurnEffect` 偏好：卷页/平移/淡入/瞬切；时长走 token（替换 400ms 硬编码）；e-ink/减少动态效果强制瞬切；持久化。
- **验收**：四种效果可切换；卷页双页书脊不回归；e-ink 瞬切；黄金图 `page_curl@*` 不变。
- **估时**：S。

#### RDR-06 双页分组持久化

- **需求**：把“从这一页起分组”从会话内改为按书（或按系列）持久化；提供“恢复自动分组”；JSON 存档容错。
- **验收**：退出重进保持分组；换书不串；恢复自动后按宽页/封面规则；单测 + 黄金图。

- W0：FIX-01/02/03（设置/阅读器）与 FIX-06/07/08（数据/UI）可并行；FIX-04/05/09 独立。
- W1：QUA-01 必须先做；之后 RDR-01/05 与 RDR-02/06 可并行，但黄金图串行。
- W2：LIB-03 与 SER-02 共用选择控制器，先做控制器；UI-01 与功能可并行，但黄金图最后统一重生成。
- W3：SCH-02 的 API spike 先做；DLD-01/02 可与 SET-01 并行。
- W4/W5：HIS-01 是硬前置；PLT/I18N/A11Y 可与 Insights 并行。

### 4.3 不建议并行的

- UI-01（玻璃收敛）与各页面功能改造：避免黄金图反复重生成；先定 token，再逐屏改。
- I18N-01 与新增文案：等 W3 功能文案稳定后再做，否则 key 反复改。
- A11Y-01 与大规模布局改造：等 W4 平板两栏后再走查。

## 5. 测试与验收策略

### 5.1 按需求类型

| 类型 | 要求 |
|---|---|
| 纯逻辑（方向/预设/分页/session/筛选） | 单测；边界 0/越界/未知/RTL/宽页 |
| Repository / API | 真实 fixture + 契约测试；新端点先存 `test/fixtures/` |
| UI 组件 | widget 测试 + 黄金图（手机 light、平板 dark、e-ink；必要时 1.3×/2.0×） |
| 状态机（下载队列/session） | 状态迁移单测 + 重启恢复测试 |
| 性能（滑杆/玻璃/大列表） | 低端 Android/模拟器 profile；无 jank；不新增每行 BackdropFilter |
| 无障碍 | 语义测试 + TalkBack/VoiceOver 人工走查 |
| 设备 | `dart run tool/ci.dart install`；实际操作本次路径 |

### 5.2 每个需求的 DoD

- [ ] 代码 + 单测/widget 测试
- [ ] 新增/变更 UI 有黄金图，并用 `read_image` 自查
- [ ] 涉及 API：`KomgaUrls` + fixture + 契约测试
- [ ] 相关 `docs/` 更新
- [ ] `dart run tool/ci.dart check` 全绿
- [ ] `dart run tool/ci.dart install` 设备走查
- [ ] 单文件 ≤350 行、单类 ≤300 行

### 5.3 每个迭代的出口

- 所有 ticket 完成；无 P0/P1 回归。
- 黄金图全量通过；新增图人工看过。
- 设备走查清单签字（本仓库单人，写进 PR 描述）。
- 更新 `CHANGELOG.md` / `docs/roadmap.md`。
- 单独提交/推送；打 tag `v0.x.0-wN`（可选）。

### 5.4 Issue / PR 拆分规范

**Issue 标题**：`[FIX-01] 墨水屏探测贯通阅读器`

**Labels**：`area/reader`、`area/library`、`area/search`、`area/downloads`、`area/settings`、`area/ui`、`area/data`、`priority/P0`、`iteration/W0`、`size/S`。

**Issue 必填**：
- 现状（代码/行为/证据）
- 目标（可验收的行为，不写“优化一下”）
- 不做什么（防蔓延）
- 验收清单（含测试/黄金图/设备）
- 依赖/风险

**PR 约束**：
- 一个 PR 只做一个需求；纯重构与行为变更分开。
- UI 变更附 before/after 黄金图；用 `read_image` 自查。
- 新增 API 调用必须带 fixture/契约测试；否则不合并。
- 不为了让测试通过改断言；黄金图变更要能说出“为什么这次渲染变了”。

## 6. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|

## 7. 明确不做（P3）

| 需求 | 理由 |
|---|---|
| WASM 外部图源 / 内置商店 / 本地导入 / 网盘 | 与 Komga 客户端定位冲突；版权/维护成本高 |
| Panels View / 逐格阅读 | 需要 ML；Panels 多年仍实验；Komga 场景弱 |
| Live Text / OCR 词典 / 实时翻译 | 平台 ML 依赖强；优先阅读体验 |
| AniList / MAL / Shikimori 追踪 | Komga 本身就是追踪源 |
| 本地分类/文件夹 | 用 Komga 收藏集/阅读列表替代；不再造一套本地分类 |
| 按书覆盖阅读设置 | 按系列覆盖已覆盖“漫画连载”场景；单本覆盖低频，避免设置三层 |
| 多用户/服务器重命名 | 自建库单用户为主；低频，等需求 |
| Panels 账号 / iCloud 同步 | 服务端真值 + outbox 已是更优解 |
| 内容锁（Face ID） | 自建库有账号权限；需求弱 |
| 多主题 / 可替换图标 | 收益低；先做层级/密度 |
| 新章通知 / 后台轮询 | Komga 无 push；成本/收益比低，等明确需求 |
| 页滤镜（降噪/锐化/去摩尔纹） | 图像处理链复杂；先做去白边 |
| 下载压缩 / 后台下载 / 断点续传 | 当前整本下载已够用；后续按用户反馈 |
| 全 App 键盘快捷键 / 手柄 | 移动优先；iPad 键盘用户少，P3 |
| 诊断日志导出 | 有系统日志；等需要支持时再加 |

## 9. 一页执行摘要（给排期用）

- **第 1–2 周（W0）**：只修 9 个 P0，冻结新功能；目标“现有功能可信”。
- **第 3–4 周（W1）**：拆阅读器 + 滑杆/目录/AA/设置分组/动画/分组持久化。
- **第 5–7 周（W2）**：书架标题/筛选状态、多选、置顶、书列表排序、系列批量/下载全部、玻璃收敛；按 3 周排。
- **第 8–9 周（W3）**：搜索历史/facets/分页、下载设置/队列、设置 IA；**MVP 发 RC**。
- **第 10–11 周（W4）**：session/History/最近阅读、收藏集封面、本地备份、平板两栏。
- **第 12–13 周（W5）**：Insights、iPad 布局、数据层 i18n、a11y、黄金图补齐；**完整版**。
- **第 14–15 周（W6）**：点击区、自动滚动、收藏集 CRUD、语言扩展；按需裁剪 + 缓冲。
- **每个迭代固定**：周一排期/依赖检查；周三中检；第二周末 `ci.dart check` + 设备走查 + 提交推送。
- **不插队**：新需求先写进 backlog，按 P0/P1/P2 重排；P0 未清不接新功能。
- **估算纪律**：上述为 1 人 + Agent 的基线；若 Agent 只能做测试/黄金图，不参与设计决策，按 17–18 周排；若有两名开发并行，W2/W4 可各压缩 1 周。
- **如果只有 6 周**：W0 全量 + RDR-01/02/03 + SER-01/03 + SCH-01/03；不碰 History/平板/收藏集，先把“读得顺 + 找得到 + 下得全”做出来。
