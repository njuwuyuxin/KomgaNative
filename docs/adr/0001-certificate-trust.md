# ADR 0001：证书信任策略（TOFU + 固定指纹）

- 状态：已采纳
- 日期：2026-11-17
- 相关：`packages/komga_api/lib/src/tls.dart`、`apps/app/lib/src/session/session_controller.dart`

## 背景

自建 Komga 的 TLS 状况比公有云服务差得多，实测就撞上两种：

1. **反代的 HTTPS 端口被当成 HTTP 访问**：`http://host:4433/` 收到 openresty 的
   `400 The plain HTTP request was sent to HTTPS port`，正文是 HTML。客户端把 400
   当成"参数错误"，用户只看到"错误号 400"。
2. **证书过期**：同一台服务器的 Let's Encrypt 证书在 2026-07-19 过期，`dart:io`
   直接握手失败（`HandshakeException: CERTIFICATE_VERIFY_FAILED: certificate has expired`），
   表现为 `DioExceptionType.unknown`。浏览器会让用户点"继续访问"，但原生客户端默认不会。

结果是：网页端能正常登录，客户端连不上。这不是 API 版本差异，而是传输层可访问性问题。

## 决策

1. **自动纠正协议**：遇到"这个端口只接受 HTTPS"的 400 时，自动把 `http` 换成 `https`
   重试一次；成功后保存纠正过的地址。只重试一次，不隐瞒结果。
2. **TOFU + 固定指纹**：证书不被系统信任时，抓下证书把 CN / 颁发者 / 有效期 / SHA-256
   指纹摊给用户，用户明确点"仍然连接"后才放行，并**只固定这一张叶证书的指纹**。
   之后的请求只放行指纹一致的证书；证书一变（续期、被替换、中间人）就重新询问。
3. **默认严格**：没有任何"全局忽略证书"的开关或默认值；没信任过就是系统默认校验。
4. **指纹算法用 SHA-256**（`package:crypto`，此前已是 test/coverage 的传递依赖，
   这里升级为直接依赖，依赖树没多出任何包）。不自己在 Dart 里手写 SHA-256。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 无条件接受所有证书（`badCertificateCallback = (_) => true`） | 等于关掉 TLS 的认证，客户端无法区分"我的 NAS"和"劫持者"；一个开关毁掉整条链路的完整性 |
| 只提示用户"去续证书" | 用户往往拿不到反代/证书的控制权（NAS 厂商自带 DDNS + 反代），问题不会自己消失 |
| 用系统信任链 + 自签名证书导入系统 | Android 7+ 用户证书对应用默认不生效，iOS 侧还要描述文件；对"装个 App 就能用"是灾难 |
| 固定证书公钥（HPKP 风格，跨续期） | 续期会换密钥，用户就得重新配置；对个人服务器过度设计 |
| 手写 SHA-256 | 密码学原语手写一遍就是给自己挖坑，且无法复用标准测试向量 |

## 后果

- 证书**过期**时用户仍能用，但每次提示都写明"已过期/自签名"，不假装安全；
- 证书**续期**后指纹变化，会再问一次——这是设计目标（不是 bug），
  文案里明说"下次一张不同的证书会被拦下"；
- 只固定叶证书，不校验链：对自签名/自签 CA 场景足够，且实现简单；
  需要严格 PKI 的用户本来也不会遇到这个面板；
- `komga_api` 因此依赖 `dart:io`（`HttpClient` / `X509Certificate`），
  该包只服务原生平台，不做 Web 目标。
